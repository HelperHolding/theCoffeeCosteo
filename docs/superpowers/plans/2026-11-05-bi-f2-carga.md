# BI «The Coffee México» — F2 (carga de ventas y piloto) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que el corte de cada 10 minutos, el cierre de las 5:30 y el script de historial también guarden las ventas por línea en `bi_lineas`. Además: un script que exporta totales para cotejarlos con Zoho, y un piloto de 6 tiendas cotejado antes de cargar la historia completa desde 2024.

**Architecture:**
- **Mismo recorrido, un guardado más.** `cortar` (`lib/sucursales/corte-servidor.ts`) ya lee cada tienda y día con `leerVentana` + `conRappi`. Por cada día leído:
  1. guarda el resumen, como ya lo hace;
  2. convierte esos mismos pedidos en líneas con una función pura (`lib/bi/lineas.ts`);
  3. llama a `bi_guardar_dia` con `p_rappi_portal = !!cfg.rappiPortal`.
- **Altas de tiendas.** Antes de guardar, asegura que cada tienda configurada exista en `bi_tiendas` (las altas faltan solo en tiendas nuevas).
- **Rappi Turbo.** Se marca en la lectura de servicio del portal (`rappiServicio`) con el canal de la tienda de Rappi.
- **Historia.** Sale del mismo `scripts/sucursales/corte.ts` con `--desde/--hasta`, que ya escribe el resumen.
- **Cotejo.** Un script nuevo exporta a `datos/` los totales por tienda × día (y por método de pago), leídos con la llave de servicio.

**Tech Stack:** TypeScript, Supabase JS (llave de servicio), PGlite + Vitest. No toca Next salvo lo que ya usa `corte-servidor`.

**Spec:** `docs/superpowers/specs/2026-11-05-bi-the-coffee-mexico-design.md`. **Base:** `docs/bi/01-BASE.md` (sección «Contrato de carga (F2)»).

## Global Constraints

- **Contrato de carga** (`docs/bi/01-BASE.md`):
  - `pedido = String(PedidoNormal.id)`;
  - `linea` = índice 1-based dentro de `PedidoNormal.lineas`;
  - `codigo = l.codigo` (la base lo normaliza con `bi_codigo`);
  - `importe_cent = importeLinea(l)`;
  - `unidades = 1` por línea;
  - `hora = floor(segundo / 3600)`;
  - `canal = origen`;
  - `metodo_pago = metodo`, `tipo_pago = tipo`;
  - `smartphone = (origen === 'app')`;
  - `opcion_consumo = null`;
  - la tienda debe existir en `bi_tiendas` antes de `bi_guardar_dia`;
  - `p_rappi_portal = !!cfg.rappiPortal` en cada guardado `pos`.
- **Un fallo del BI no tumba el corte.** Si `bi_guardar_dia` falla para una tienda y día, el resumen del Tablero México se guarda igual. La falla se anota en `sucursales_cortes.mensaje` y en el resultado del corte.
- **Un día que no se pudo leer** (`estado === 'error'`) no se guarda en el BI, igual que en el resumen.
- **Sin cambios de comportamiento** en las páginas de Sucursales ni en el Tablero México. Solo cambia `tipo` en pedidos Rappi Turbo del portal, que hoy nadie lee (`grep "\.tipo"`).
- **Seguridad y flujo de trabajo:**
  - no tocar `.env.local`;
  - no correr nada contra producción;
  - no hacer push ni merge sin OK;
  - los scripts con llave de servicio los corre Sebastián.
- **Migraciones:** las 40 y 41 siguen sin aplicar. Las filas nuevas de pagos se agregan a `docs/bi/zoho/pagos.json` y la 41 se **regenera** con el CLI.

```ts
// lib/bi/lineas.ts
import { importeLinea, type PedidoNormal } from '../sucursales/normalizar';

/**
 * Ventas por línea para el BI (docs/bi/01-BASE.md, «Contrato de carga (F2)»): una fila por línea del pedido, con el
 * importe de la línea más sus modificadores (IVA incluido, como «Net Amount (Local)» de Zoho). Sin datos de clientes.
 * La base normaliza el código (bi_codigo); aquí va tal como lo dio el POS (defaultCode o, si falta, productName).
 */
export interface LineaBi {
  pedido: string;
  linea: number;
  hora: number;
  canal: 'mostrador' | 'app' | 'rappi' | 'desconocido';
  metodo_pago: string;
  tipo_pago: string;
  smartphone: boolean;
  opcion_consumo: null;
  codigo: string;
  nombre: string;
  unidades: number;
  importe_cent: number;
  descuento_cent: number;
}

/** El POS manda el importe ya descontado y el descuento de línea como porcentaje: se deriva el monto. */
const descuentoCent = (importeCent: number, pct: number) =>
  pct > 0 && pct < 100 ? Math.round(importeCent / (1 - pct / 100)) - importeCent : 0;

export function lineasBi(pedidos: PedidoNormal[]): LineaBi[] {
  return pedidos.flatMap((p) =>
    p.lineas.map((l, i) => ({
      pedido: String(p.id),
      linea: i + 1,
      hora: Math.min(23, Math.floor(p.segundo / 3600)),
      canal: p.origen,
      metodo_pago: p.metodo || 'SIN_DATO',
      tipo_pago: p.tipo || '',
      smartphone: p.origen === 'app',
      opcion_consumo: null,
      codigo: l.codigo,
      nombre: l.nombre,
      unidades: 1,
      importe_cent: importeLinea(l),
      descuento_cent: descuentoCent(l.importeCent, l.descuentoPct),
    })),
  );
}
```
